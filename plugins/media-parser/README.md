# 流媒体聚合解析 · media-parser

Roost 原生插件，版本 `0.4.2`。收到受支持的分享链接后，在本机 Python 引擎中解析和下载，再使用原消息的被动回复上下文依次发送正文、图片、视频、语音或文件。默认关闭翻译，解析流程不调用模型。

插件提供可选的 B 站私信提醒：默认关闭，使用同一份共享 B 站登录，只把之后新增的入站私信转发到已绑定的机器人主人 QQ 私聊。管理页可勾选“发送到群”并选择一个宿主已识别、已启用的群作为唯一自动通知目标；默认仍是主人 C2C，不会同时重复发送到私聊和群。它独立于 Python 引擎，引擎准备失败或停止不会停掉已登录的私信读取；私信故障也不会使原有媒体解析入口不可用。

完整引擎源码、原始源码包与许可证随插件提供。来源和适配说明见 [SOURCES.md](./SOURCES.md)，发布说明与证据层级见 [TEST-REPORT.md](./TEST-REPORT.md)。

## 0.4 更新范围与验证边界

`0.4.2` 将小黑盒一对一私信转为**正式原生能力**：已完成实验和用户真机验收，能力声明为 `verified: true`，不再输出 `experimental` 标记。功能仍默认关闭，用户显式保存启用后才读取；页面和命令使用同一套原生运行时。扫码、手动登录、查询、开关、测试、待发、领取和查看等现有功能保持不变。

2026-11-28 用户已明确确认真机人工验收完成。独立本地日志审查记录到：真实二维码申请和轮询 HTTP 200；账号校验 HTTP 200；凭据保存并 accepted；会话／消息读取 HTTP 200；一次内置测试通知投递为 `delivery`／`send`／`sent`，`hostSent: true`、`sent: 1`。内置测试通知不是新私信正文端到端转发的独立证据，不能据此推断双账号收发。

多次基线结果仍为 `XHH_WATCHING_LIMITED`、`baselineComplete: false`，因此完整分页、历史恢复、未读副作用、图片／分享子能力和风控恢复等没有逐项独立实测记录，记为未逐项独立证实；这不否定用户已确认的整体人工验收。此前 B 站文字群投递、重复扫描仍仅一条、重载后没有重复，已由用户确认。

`0.4.2` 修正已确认的小黑盒扫码签名端口缺陷：JS 移植遗漏了 Python 参考 `_mix_columns` 中保留的最后两个未变换校验字节。独立固定参考向量确认旧实现得到 `SPSPW16 / IZITX58 / VV10Y48`，正确值为 `SPSPW24 / IZITX11 / VV10Y50`。同时保留冷却／预算分类修复：本地冷却或预算阻止二维码请求时报告 `XHH_COOLDOWN`／`XHH_BUDGET` 和剩余等待，不再误报 `XHH_TIMEOUT`。传输保持 `0.4.1` 的可选 Electron `net` 或 `node:https`、固定 HTTPS GET、无自动重定向／换通道、15 秒总截止；既有冷却、预算和历史数据不重置、不削弱、不绕过。

B 站侧保留 0.3.2 的凭据提交 guard、提交后 revision 元数据写入、`BILI_STORAGE` 分类和显式检查替换旧终态错误的修复。0.4.0 记录的小体量脱敏事件仍接入认证维护路由，并可在页面展开查看。

本轮沿用已验收的 0.2 B 站登录、历史基线、账号分区、待发队列、主人绑定及指定群通知。原始引擎归档、Python 引擎和握手版本 `0.1.0` 保持原样。

私信开关及间隔请在本插件“平台接入与私信提醒”区域保存，或使用对应 QQ 命令。宿主通用插件配置的外部修改没有可供本插件订阅的配置变更事件；通过该入口更改后，应在插件页保存一次或热重载后核对实际监听状态。页面显示“配置已启用”不能单独证明服务已经开始同步。

管理页的平台接入选择与原有 31 个媒体平台输出模式分别管理。切换 B 站／小黑盒视图只更换当前管理对象，不代表启停、退出登录或重建历史基线。旧 `/解析 私信 <操作>` 始终指向 B 站；小黑盒使用显式的 `/解析 私信 小黑盒 <操作>`。

小黑盒原生登录和私信读取已接入并转为正式能力。具体证据分级和未逐项证实范围见 [小黑盒协议记录](./docs/xiaoheihe-dm-contract.md)。

升级涉及请求调度和间隔迁移。安装前请按 [迁移与回退说明](./MIGRATION-ROLLBACK.md) 暂停同步，等待旧代次写入完成，并备份 0.2 插件代码与整个插件数据目录。

请求参数、拒绝分类和人工恢复命令见 [请求调度说明](./docs/request-policy.md)。例如 `/解析 私信 B站 恢复` 只释放受控恢复流程，仍保留服务端要求的等待。

## 安装与首次准备

将完整的 `media-parser` 目录放到正在使用的 Roost 安装目录的 `plugins/` 下，通过宿主插件页面启用或热重载。入口是 `index.js`，不是外部插件的 `plugin.json`。独立安装包解压后同样得到这个目录。无需修改 Roost、DSH 或其他插件源码，也不需要 QQA。

依赖：

- Python 3.10 或以上，带 `venv` 和 `pip`。可在管理页指定 `pythonPath`，Windows 也会尝试 `py -3`、`python`。
- 首次准备在独立虚拟环境安装 `aiohttp>=3.9,<4` 和 `pillow>=10,<13`，需要能够访问 Python 包源。
- ffmpeg 用于部分视频音轨合并、格式转换和压缩音频检查。可以配置 `ffmpegPath`。缺少时仍可处理文字、图片及不需要合并的视频。
- 短语音复用本机 Roost 的语音转换模块和已安装的 `silk-wasm`；未安装编码依赖会回退为完整音频文件，不在聊天处理中自动安装编码依赖。

`setup()` 只注册功能并在后台发起准备。管理页会显示准备中、就绪或具体错误。虚拟环境解释器存在时仍会检查依赖导入和引擎 `--check`；安装中断后可用“准备／修复依赖”继续恢复。首次安装时间取决于本机 Python、包源和网络状况。

插件声明 `frameworkVersion: >=1.1.5`，本次实际核对和验证的宿主版本以测试报告为准。语音转换使用集中兼容适配器动态查找实际安装目录；其他版本需要重新验证接口。

## 使用

普通群聊和 C2C 私聊中直接发送分享链接即可。默认不额外要求 @；机器人能否收到群消息仍由 QQ 事件订阅、宿主白名单、暂停闸和插件会话开关决定。每条消息去重后最多处理三个链接，保留原文顺序和资源所需的 query、网易云 fragment 等参数。

| 命令 | 用途 |
|---|---|
| `/解析 <分享链接>` | 手动解析 |
| `/解析 状态` | 查看公开的引擎和队列状态 |
| `/解析 平台` | 查看 31 个平台的输出模式 |
| `/解析 开`、`/解析 关` | 校验群管理权限并说明宿主群级开关入口，见下方限制 |
| `/群插件 开 media-parser` | 使用宿主的同一份分群插件配置启用 |
| `/群插件 关 media-parser` | 使用宿主的同一份分群插件配置停用 |

**群级开关的宿主限制：**当前公开 `ctx` 没有写入 `cfg.plugins.groups` 的方法，而且群级停用后宿主会在命令分发前拦截该插件。因此第一版使用宿主已有的 `/群插件` 命令或面板分群设置完成修改；`/解析 开|关` 只作权限校验和入口提示。这一项与计划书中的直接别名行为存在差异。插件没有另存群名单，也没有借此修改全局配置。

只有普通群聊和 C2C 适配发送；频道和频道私信暂未支持。结构化卡片必须由宿主实际提供 URL 才能提取，不能从“卡片消息”占位文字猜测地址。番剧、多 P、图集和音乐沿用引擎的既有语义，不默认下载整个合集。

自动解析遇到尚未就绪的引擎会放行；手动命令会提示准备中。天生仅文字的结果默认放行，可在配置中启用。媒体下载失败后保留说明文字，和天生仅文字结果分别处理。只有内容确认发送或进入待确认状态后才认领消息；发送方法返回 `null` 或全部失败时不会提前认领。

## B 站私信提醒（默认关闭）

所有私信子命令都要求普通 C2C 私聊，并且当前消息发送者通过 `ctx.isOwner(msg.userId)` 校验。群聊只提示移到主人私聊，非主人只得到权限提示；命令回复不包含 UID、二维码内容或私信正文。宿主未提供 `isOwner` 时一律拒绝。

正常顺序：

```text
主人（QQ 私聊）：/解析 私信 绑定
机器人：已绑定当前主人私聊作为接收目标。
主人：/解析 私信 登录
机器人：展示二维码，提醒使用 B 站手机客户端扫码并确认。
主人：/解析 私信 开
机器人：正在建立历史基线；完成后只提醒之后的新私信。
```

| 命令 | 用途 |
|---|---|
| `/解析 私信` | 显示私信用法、状态和下一步 |
| `/解析 私信 绑定` | 把当前真实 C2C 主人私聊保存为唯一接收目标；不接受文本自报 QQ 号 |
| `/解析 私信 登录` | 生成内存二维码；也可在管理页手动填写 Cookie |
| `/解析 私信 状态` | 查看登录、监听、绑定、积压、上次成功和退避状态 |
| `/解析 私信 开` | 在登录有效且已绑定后启用，进入初始化或恢复进度 |
| `/解析 私信 关` | 暂停抓取和自动投递，保留账号、绑定和进度 |
| `/解析 私信 检查` | 立即检查一次；复用正在运行的任务并遵守退避 |
| `/解析 私信 测试` | 向当前选择的自动通知目标发送测试通知，不消耗真实私信；默认是已绑定主人私聊 |
| `/解析 私信 待发` | 显示待发送、待核对、未知数量和领取指引 |
| `/解析 私信 领取` | 在当前主人 C2C 回复预算内分批领取明确未投递内容 |
| `/解析 私信 查看 <编号> [页码]` | 重复查看保留期内的单条内容，可指定续页；标注为重复查看，不改变原投递结果 |
| `/解析 私信 退出登录` | 清除本插件共享 B 站登录并暂停提醒；不调用全站注销 |

小黑盒私信命令（仍要求普通主人 QQ 私聊，`chatId === userId`，异步操作后再次校验主人）：

| 命令 | 用途 |
|---|---|
| `/解析 私信 小黑盒 登录` | 在主人私聊或认证管理页获取扫码；二维码不进入群聊、公开状态或日志 |
| `/解析 私信 小黑盒 状态` | 查看登录、监听、受限发现、绑定和安全错误；不输出 UID、Cookie、正文或 QR 参数 |
| `/解析 私信 小黑盒 检查` | 通过共享请求门禁执行一次本地/受控检查；不绕过冷却 |
| `/解析 私信 小黑盒 开` / `关` | 显式保存启用或暂停；与 B 站开关、间隔和群目标相互独立 |
| `/解析 私信 小黑盒 测试` | 仅在用户主动操作时向当前绑定目标发送带标记的测试通知 |
| `/解析 私信 小黑盒 待发` / `领取` / `查看 <编号> [页码]` | 复用普通主人 C2C 与投递账本的待发、领取和重复查看 |
| `/解析 私信 小黑盒 退出登录` | 只清除独立的小黑盒凭据分区，并暂停其提醒 |

小黑盒未绑定时沿用 `/解析 私信 绑定`，页面不能伪造主人绑定。发送仍必须有可用 owner 和共享发送预算；B 站既有 `reserveSendCall`/`rateInfo` 由两个平台共同使用，不会把总频率翻倍。

登录和启停规则：

- 登录成功只保存共享 Cookie，不会自动启用提醒，也不会自动开启 `bilibili_enhanced.use_cookie`。
- 首次启用会建立历史基线；已有未读不会批量转发。重启或热重载不会重建已有同 UID 的基线，会补拉停止期间仍可获取的新消息。
- 抓取使用持久化游标，不依赖 B 站未读数或已读状态。对方先在手机查看不会导致漏报。
- 私信与媒体解析共用凭据；换账号时旧账号的未完成内容被冻结，新账号独立建基线，不会把旧账号积压当新账号消息发出。同 UID 重新登录恢复原进度。
- 停止、启动或清理 Python 引擎只影响媒体解析，不删除私信状态或共享登录。宿主整体停用插件时会停止轮询和扫码。
- B 站网页接口可能变化、限流或要求重新登录；实际可用性以账号联调为准。QQ 主动私聊受宿主通道、关系和额度的限制，积压时使用「领取」。
- 图片和分享只转发经校验的原链/标题/说明，不自动下载附件，也不把提醒内容送回媒体解析队列。
- 状态文件按机器人实例和 UID 分区，包含绑定版本、发现进度、会话游标、消息、投递分段和限速记录。未完成消息不按缓存清理；已完成记录默认保留 7 天用于核对；上限为 1000 条未完成逻辑消息或 20 MiB 状态文件，先到先暂停抓取并保留续拉点。
- 发送前重新校验主人权限和绑定版本。`pending`、审核中和结果未知的投递不会自动重发；`ctx.delivery.fail()` 不会被用来把未知结果改成可重试。
- 退出登录会明确提示共享 Cookie 失效并影响 Cookie 增强解析；它不会注销 B 站其他设备。

群接收规则：

- 默认关闭，自动通知目标是主人 C2C。管理页勾选“发送到群”后启用群选择框；保存后该群成为唯一自动目标，不再同时发到主人私聊。
- 群候选只来自机器人最近识别到的群和当前已配置群，并通过宿主 `ctx.getGroup` 重新确认存在且启用。未知、停用或宿主未提供的群不会被接受；页面不会调用宿主群列表接口。
- 群列表可能为空；提示“群列表来自机器人最近识别的群，未出现请在目标群发一条消息后刷新”。刷新只读取最近记录，不读取群消息正文。
- 选择群后，主人绑定必须仍然有效并再次通过 `ctx.isOwner` 校验；绑定命令、状态、检查、测试、领取和查看等管理操作仍在主人 QQ 私聊中进行。
- 切换接收目标或接收模式时，旧目标下尚未尝试的批次保持冻结，不自动改发到新目标；已进入 `sending`、`pending` 或 `unknown` 的结果只通过宿主账本核对，不整批补发。
- 状态和命令只显示安全的目标类型和脱敏群标签，不返回群 ID、主人 ID、UID、发送者或私信正文；群选择接口按选择器需要只返回宿主允许的 `{id,name}` 选项。
- B 站文字群收件、重复扫描仍仅一条、重载后没有重复已由用户确认；小黑盒群目标的实际收件仍属未逐项独立证实范围。

## 配置和管理页面

Roost 插件管理页内的“解析管理”提供：

- 自动触发、私聊、@、纯文字、正文、音频模式、任务和体积预算。
- 引擎身份、准备进度、Python、ffmpeg、编码依赖、缓存和队列状态。
- 全部 31 个平台的“全部发送／仅文本／仅富媒体／关闭”模式。
- 有上限的任务历史、实际发送数量、待确认、失败和跳过原因。
- 后台准备、依赖修复、启动、停止、空闲重启和清缓存。
- B 站扫码登录、取消、检查、手动 Cookie、退出共享登录，以及私信启停、轮询间隔、系统私信范围和测试通知。
- 小黑盒原生扫码登录、取消、检查、手动 Cookie、退出登录、显式启停、独立轮询间隔、独立群目标、立即检查和测试通知；视图不再显示验收状态标记，也不显示 B 站专用系统私信选项。
- 小黑盒可折叠“验收记录”：只读本机脱敏事件表（阶段/时间/码/计数），手动刷新或展开时读取，不显示正文、完整 ID、凭据或 URL，也不自动发送。
- 自动通知目标：默认主人 C2C；勾选“发送到群”后从宿主已识别群中选择一个，支持刷新群列表和单独保存目标。
- 私信登录与监听分开的状态、初始化/追赶进度、上次成功、下次重试、待发送/待核对/未知数量和安全错误摘要。
- 输入链接后调用真实引擎的解析预览，只展示文字和媒体清单，不向聊天发送。
- 原引擎高级配置与单独保存、遮罩展示的 Cookie、Token、API Key。

页面接口在 `/api/plugins/media-parser/r/...` 下，复用宿主的页面授权令牌／面板会话、CSRF 和同源保护。插件路由不读取请求体自报的 owner 或 role。当前宿主没有向插件路由提供独立用户角色，持有该管理页面有效授权者可以执行维护操作。

常用默认值：

| 设置 | 默认值 |
|---|---|
| 自动解析、C2C | 开 |
| 群聊要求 @、纯文字结果 | 关 |
| 引擎 | 托管，`http://127.0.0.1:3199` |
| 每条消息链接上限 | 3 |
| 单文件上限 | 200 MiB，与通道硬上限取较小值 |
| 解析、下载与发送共享预算 | 300 秒 |
| 并发 | 全局 2，同会话 1 |
| 等待队列／等待时限 | 10 个／30 秒 |
| 同会话同链接去重 | 120 秒 |
| 正文／音频 | 发送正文／自动 |
| 缓存保留 | 1800 秒 |
| 热评／翻译 | 0／关 |
| B 站私信提醒 | 关 |
| 私信轮询间隔 | 300 秒，可设 180～3600；有效间隔可能因冷却或自适应降频更长 |
| 纳入系统私信 | 关 |
| 自动通知目标 | 主人 C2C；可选一个已识别群 |

高级配置沿用原引擎的 `parsers`、`message`、`download`、`proxy`、平台 Cookie 和 `translation`。翻译开关的真实字段是 `translation.enable`。修改需要重载的设置后，页面显示提示，待任务空闲时再显式重启引擎。

多个机器人使用各自数据目录和引擎身份；监听端口也需要不同。如果 3199 已被其他程序占用，修改本机器人的 `engineUrl` 端口，插件不会结束任意占用端口的进程。

## 发送限制与音频

正文使用即时回复并拆分；递归展开转发节点，保持文字、图片和视频的原始顺序。连续图片通过框架接口显式指定允许数量，并逐个记录实际投递结果。群聊和 C2C 的回复次数、时效都受宿主约束，预算不足时保留数量说明；带媒体结果不会在回复正文或说明里再次输出原始链接，避免宿主和 DSH 对同一链接再次抓取。

当前验证基线的本地文件硬上限为 200 MiB，图片／视频／语音软上限分别为 20／30／20 MiB。超软限时改为文件并说明，超硬限时跳过。文件上传和分片由框架处理。

“自动”音频策略只将经确认不超过 60 秒、体积合规且能完整编码的短音频转换成有效 SILK 语音。整首歌曲、有声内容、超时长音频和编码失败的音频发送原文件，保留完整内容。不会默认截成一分钟。选择“语音”仍遵守这些边界；“文件”直接使用完整文件。

投递键按机器人、原消息、资源和段序号生成；待确认结果不会整份重发。插件停用和热重载会取消旧代次任务，阻止后续新发送动作。已经进入宿主发送接口的动作仍由宿主和 QQ 决定最终结果，投递账本用于核对。

## 本地数据、网络和维护

运行数据均放在宿主提供的 `ctx.dataDir`：

- 引擎内容摘要对应的源码目录和独立 Python 虚拟环境。
- `engine-settings.json`：不含平台凭据的高级配置。
- `credentials.json`：单独保存的凭据。管理页只显示设置状态和遮罩。
- `bili-dm-state.json`：按 UID 分区的 B 站私信绑定、游标、消息和投递分段；绑定保留主人目标，并记录 `notifyKind`、`groupTarget` 和可选 `groupName` 作为自动通知目标。带 `schemaVersion`，串行原子写入。
- 引擎有效配置、实例身份、本地鉴权令牌、依赖就绪标记与有限日志。
- 媒体缓存、发送临时文件和有条数上限的任务记录。

代码目录只存源码、模板、原始引擎包和交付资料。首次启动不拉取上游最新代码。托管服务仅监听回环地址，所有接口要求本地令牌，并核对服务 ID、实例、版本和源码摘要。重载可以复用验证通过的健康实例；停止／重启只面向重新验证归属的托管实例。

数据 schema、升级备份和回退步骤见 [MIGRATION-ROLLBACK.md](./MIGRATION-ROLLBACK.md)。回退时先暂停私信，保留 `bili-dm-state.json` 供再次升级；不要把私信状态当媒体缓存删除，也不要自动重发已冻结或待核对内容。

用户链接、API 响应中的媒体地址、短链与重定向经过公共地址检查；DNS 检查对应实际连接地址。显式配置的 HTTP(S) 代理采用检查后的数字目标 IP，保留原 Host 和 TLS 名称。只有管理员配置的代理端点可以是私有地址；目标站点仍必须是公共地址。TikTok 原有 curl 抓页改为受检查的 aiohttp 请求，可能更易遇到平台 WAF，见平台验证矩阵。

仅允许配置缓存根内的普通媒体文件发送，检查真实路径、体积和符号链接逃逸。远程媒体先经过有大小、重定向和时间限制的下载流程落盘，再交给发送接口。ffmpeg 输入受缓存和协议、格式白名单限制。清理会检查每个删除路径，正在解析／发送的缓存有租约保护。

外部模式只支持符合本插件身份、认证和截止时间协议的同机服务，必须显式配置本地缓存根和服务凭据。其他 HTTP 服务或原 QQA 服务不会因返回了 JSON 就被当作就绪；外部实例不会由插件停止。

## 与其他插件及 DSH 的关系

监听器优先级为 40。当前检查到的 `trpg-forwarder` 为 60、`reply-judge` 为 50。`reply-judge` 的中间件可能在普通监听器前拦截链接；管理页展示诊断和可供管理员加入其 `bypassRegex` 的规则，不直接改其他插件。

Roost 外接事件会在普通插件认领前广播。若同时启用 DSH 自动聊天，本插件的 `claim()` 无法撤回已广播的事件。因此“默认解析不调用模型”描述的是本插件自身的解析流程，整台机器人的聊天是否另行调用模型还取决于宿主与其他组件。

## 本地验证

使用 Node 内置测试执行器以及安装了计划依赖的 Python：

```powershell
node --test test/*.mjs
python -m unittest discover -s test -p "test_*.py" -v
python engine/run_engine.py --config <数据目录中的有效配置.json> --check
```

宿主原生测试脚本可从包含 `plugins/media-parser` 的工作目录调用：

```powershell
node <Roost安装目录>/scripts/test-plugin.mjs media-parser --list
node <Roost安装目录>/scripts/test-plugin.mjs media-parser 解析 状态
```

真实群聊验收需要用户在测试群发起消息。解析预览和自动化模拟不能证明 QQ 中的视频音轨、语音播放或图集显示已经通过。B 站私信的人工验收已由用户确认；小黑盒的分项能力按日志证据和未逐项证实范围记录，见测试报告与协议记录。
