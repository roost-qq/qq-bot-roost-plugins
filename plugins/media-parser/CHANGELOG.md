## 0.4.2 — 2026-11-28（小黑盒转正式、扫码签名修正、冷却区分与人工验收确认）

- 修正已确认的签名端口缺陷：JS 实现的 `mixColumns` 只返回前四个变换字节，遗漏了 Python 参考 `_mix_columns` 保留的最后两个未变换校验字节。独立固定参考向量确认旧值 `SPSPW16 / IZITX58 / VV10Y48` 与正确值 `SPSPW24 / IZITX11 / VV10Y50` 不一致；本次只修该缺陷，不改 nonce、时间、路径、参数、请求头、凭据或算法其余部分。
- 保留冷却／预算分类修复：本地冷却或预算阻止二维码请求时报告 `XHH_COOLDOWN`/`XHH_BUDGET` 和剩余等待，不再误报 `XHH_TIMEOUT`；没有派发网络时也不声称发生网络超时。既有冷却、预算和历史数据不重置、不削弱、不绕过。
- 用户于 2026-11-28 明确确认真机人工验收完成。独立本地日志审查确认：真实二维码申请和轮询 HTTP 200；账号校验 HTTP 200；凭据保存并 accepted；会话／消息读取 HTTP 200；一次内置测试通知投递为 `delivery`/`send`/`sent`，`hostSent: true`、`sent: 1`。内置测试通知不是新私信正文端到端转发的独立证据。
- 小黑盒私信已完成实验与用户真机验收，转为正式能力：内部能力声明改为 `verified: true`，彻底移除能力对象、状态模型和平台摘要中的 `experimental` 标记；页面、命令和配置标签删除“原生接入验收中”“受控验收接入”“验收中”等文案。默认仍为 `enabled: false`，所有检查、冷却和脱敏边界不变。
- 多次基线仍为 `XHH_WATCHING_LIMITED`、`baselineComplete: false`；完整分页、历史恢复、未读副作用、图片／分享子能力和风控恢复等未逐项独立证实，这不否定用户确认的整体验收。保留“读取可能影响未读状态”和“无法证明完整性时保持 limited/gap”的限制说明。
- 传输保持 `0.4.1` 的可选 Electron `net` 或 `node:https`、固定 HTTPS GET、无自动重定向／换通道、15 秒总截止。
- 插件版本统一 0.4.2，引擎与握手协议 0.1.0 不变；市场整理对文档和字面量元数据做等价适配，不提升版本号。

## 0.4.1 — 2026-11-28（小黑盒原生 HTTP 兼容候选与有限进度诊断）

- 已安装 `0.4.0` 在用户手动申请小黑盒二维码时记录一次真实 `XHH_TIMEOUT`，但超时根因尚未证实；本版不声称平台可达性或扫码已经恢复。
- 新增原生 HTTP 兼容候选：能力可用时可选 Electron `net.request`，否则使用标准 `node:https.request`，不依赖全局 `fetch`。只访问既有固定 HTTPS GET 路径，不自动重定向或切换传输，共享请求策略和 15 秒总截止保持不变。
- 新增有限进度诊断：仅输出有限操作、传输和网络阶段枚举，以及耗时、字节、状态数字和有限 `XHH_*` 错误码；不记录 URL、Cookie、二维码、完整 ID、正文或原始异常，观察者异常不能改变 HTTP 行为。
- 验收记录只读取本机脱敏诊断；真实扫码、账号和私信协议仍未验收，`verified` 仍为 false、`experimental` 仍为 true、默认关闭。
- 插件版本统一 0.4.1，引擎与握手协议 0.1.0 不变；构建工具生成新的 0.4.1 交付、源码清单和 ZIP 逐文件摘要。
- 该版为实验接入；0.4.2 已完成实验与用户真机验收并转为正式能力。

## 0.4.0 — 2026-11-28（小黑盒原生验收接入）

- 新增原生小黑盒运行时集成：默认关闭，用户可在管理页或 `/解析 私信 小黑盒` 命令中显式启用/关闭；`verified` 仍为 false，页面准确显示“原生接入验收中”，不称协议已验证。
- 小黑盒注册能力改为支持私信、扫码、手动登录、poll 传输，`experimental: true`、`available: true`；主流程不再因 `verified: false` 拒绝使用。
- 运行时在 B 站私信初始结果 settled 后启动，失败不阻断小黑盒登录；共享 B 站 owner 绑定和 `reserveSendCall`/`rateInfo` 预算，不另建翻倍频率。停用立即 abort，并将 xhhReady/flush 纳入代次交接。
- 新增认证 `GET /dm/providers/:provider/acceptance`，严格校验 0～100 的整数 limit；返回脱敏验收快照。B 站明确提示该接口不适用，未知平台仍拒绝。
- 管理页小黑盒视图新增可折叠验收记录、手动刷新和有限事件表，全部使用 `textContent`；不输出正文、完整 UID/目标/消息 ID、凭据或 URL，切换视图丢弃迟到结果。
- 请求策略增加 `XHH_CANCELLED/AUTH/RATE_LIMIT/RISK/CHALLENGE/TIMEOUT/NETWORK/HTTP/RESPONSE/API` 分类，保持 B 站既有规则；服务端更晚的 Retry-After 与跨页数据预算继续生效。
- 设置去掉小黑盒强制关闭/真值拒绝，默认仍为 false；B 站提交 guard、revision 元数据、`BILI_STORAGE` 和显式检查修复原样保留。
- 该版为实验接入；0.4.2 已完成实验与用户真机验收并转为正式能力。
- 插件版本统一 0.4.0，引擎与握手协议 0.1.0 不变；新增 `build-native-release.py` 与 `install-native.ps1`，输出本目录 `delivery/media-parser` 和 `media-parser-0.4.0.zip`。
- 未完成项：真实小黑盒扫码、分页边界、历史恢复、未读副作用、图片/分享子能力和 QQ 实际收件仍待用户手动验收；此前已实测 B 站文字群投递、去重和重载。

## 0.3.2 — 2026-11-28（登录保存修正候选版）

- 保持凭据原子提交前的调用方 guard 与停用检查：取消、换代或外部凭据变更仍在 rename 前拒绝迟到提交。
- 修正自身提交后的判定：credentials 已成功 rename 并发布新 revision 后，本次操作的 `engine-settings.json` 元数据写入不再被同一提交造成的 revision 变化误判为取消，正常完成保存。
- 凭据已提交但后续元数据写入发生真实 IO 失败时，手动登录返回 `BILI_STORAGE` 错误，不再返回 `cancelled`，也不会报告成功；错误只携带有限的已提交 revision，不包含 Cookie。
- 显式成功的登录检查可以替换旧的终态扫码错误；后台账号检查仍不抹掉扫码错误，正在进行的二维码会话继续优先。
- 其他解析、私信、请求门控、迁移和页面逻辑保持原样；引擎协议仍为 0.1.0。本版仅完成离线复测，真实重新扫码与再次重载仍待用户手动验收。

## 0.3.0 — 2026-11-27

### 管理页与平台视图

- 管理页按计划拆为 10 个顶层区块，仅引擎、触发投递和本机设置默认展开；真实解析预览独立折叠，平台输出和日志任务位于最后。
- 新增“平台接入”快捷入口，展开并定位平台选择器。群目标、原平台输出模式、凭据及维护操作继续使用现有入口。
- 固定 B 站／小黑盒平台视图，切换不启停、不退出登录、不重建基线；平台偏好按机器人保存，仅记录非敏感平台 ID。
- 页面按区块和可见性读取本地快照，迟到响应受平台、请求和账号会话版本约束。

### 请求、冷却与兼容

- 轮询默认改为 300 秒，范围 180–3600 秒。旧值低于 180 秒时一次性迁移为 300 秒；原有效值与账号、目标、基线、队列保留。
- 增加统一出站协调器，覆盖同步分页、立即检查、账号校验、手动 Cookie 与扫码；同宿主进程内共享平台请求预算和冷却。
- 限速元数据原子保存，损坏或保存失败时安全暂停；服务端 `Retry-After` 不受本地冷却上限截短。
- 恢复按完整同步流程推进，保留精确续拉位置；提供主人 C2C“恢复”操作，仍遵守服务端等待。
- 增加 `/dm/providers/*` 统一路由及显式平台命令，旧 `/bili/*` 和旧私信命令继续指向同一 B 站服务。
- 小黑盒私密配置与 B 站分区隔离，并从所有 Python 有效配置合并中排除。
- 插件展示版本为 0.3.0，原始引擎归档、vendor、Python 服务和引擎协议 0.1.0 保持不变。

### 未完成的实号范围

- 小黑盒登录、一对一私信及 QQ 转发尚未取得两个授权测试账号的实测证据，能力保持关闭；不把社区通知或可切换的占位界面视作私信接入完成。
- 本轮自动化与隔离页面验证不能代替真实 B 站／QQ 联调或连续两小时运行观察。结果和具体未验证项分别记录在测试报告与小黑盒协议记录。

## 0.2.0 — 2026-11-25

### 静默启动与进程

- 统一托管 Python 子进程参数：Windows 使用 `windowsHide: true`、`detached: false`、`shell: false` 和独立日志；其他平台保留相应生命周期策略。
- 引擎准备、依赖修复、启动/停止/清理仍由现有托管服务处理，健康实例复用和归属校验不变。

### B 站登录与共享凭据

- 新增用户主动扫码登录、取消、检查、手动 Cookie 和退出共享登录；二维码只以内存 PNG data URL 或原生图片回复提供。
- 登录成功不自动开启私信提醒，也不自动开启 Cookie 增强解析。
- 共享 Cookie 仍由 `settings.js` 的串行原子写入管理；退出登录只清除本插件共享值，不调用全站注销。
- 旧布局中的 B 站 Cookie 归一化为单一根位置，其他平台凭据保持不动。
- 迁移旧配置中的唯一登录值时，先原子保存凭据，再清理旧来源；磁盘失败和迁移期间停用插件不会提交迟到的清理。

### B 站私信提醒（默认关闭）

- 新增 `biliDmEnabled`、`biliDmPollSeconds`（60～1800）、`biliDmIncludeSystem` 配置。
- 新增独立私信运行时：会话发现、首次基线、反向消息分页、持久化游标、账号隔离、请求预算与网络退避。
- 私信状态使用 `bili-dm-state.json`（`schemaVersion: 1`），按 UID 分区，未完成消息与投递分段串行原子保存。
- 新增主人 C2C 绑定、稳定投递键、分段正文、只读账本核对、待发送/待核对/未知分类和被动领取。
- 私信失败、状态损坏、登录失效或网络故障不会禁用原有媒体解析；`runtime.ready` 不因私信失败而拒绝。
- 热重载先取消旧代次网络/扫码，并在新设置与私信状态加载前等待旧代次存储写入尾部；已经进入宿主发送的动作只通过账本核对，不整批补发。
- 退出登录会提示共享 Cookie 对增强解析的影响；暂停提醒保留账号、绑定和进度。

### 管理页与命令

- `/解析 私信` 在媒体链接处理前分发，支持绑定、登录、状态、开、关、检查、测试、待发、领取、查看和退出登录。
- 所有私信子命令要求普通 C2C 且 `ctx.isOwner(msg.userId)`；群聊只提示移到私聊，非主人只得到权限提示，不接受请求体或聊天文本提供的目标。
- 新增认证前缀内的 `/bili/login/*` 与 `/bili/dm/*` 维护路由；写操作使用 POST/PUT，不提供页面绑定、正文、发送者或目标查询路由。
- 管理页新增登录、二维码、手动 Cookie、提醒设置、分离状态、积压/核对、测试通知；页面不读取私信正文，QR 只在专用登录响应中返回。
- 公开 `/status`、`/config`、仪表盘和媒体任务记录不包含私信绑定、UID、发送者、正文或内部运行时对象。

### 运行时复核修复与群目标选择

- 旧代次命令在异步账号检查或停用后不再写入配置；设置保存增加可选 `isActive` 和提交 guard，在串行队列内及文件重命名前复核，初始加载继续先等待旧代次写入尾部。
- 所有私信命令要求普通 C2C 且 `chatId === userId`（缺失 `chatId` 时使用原生 `userId`），并在异步操作后复核活跃代次与当前主人；二维码不会发到伪造会话。
- 私信状态只输出有限安全码、安全发现阶段、脱敏目标和白名单字段，不再复制任意 `reasonCode`、`errorCode`、`errorSummary` 或 `discovery.phase`。
- 领取和重复查看已在宿主被动回复中发送内容，命令不再追加第五段缓冲回复；查看支持可选数字页码和精确续页提示，前缀动态取自宿主。
- 管理页测试通知只委托已保存绑定，不再伪造 QQ 入站消息。
- 退出登录先暂停私信并取消扫码，再等待配置保存；保存或清除 Cookie 失败会明确拒绝，不显示虚假成功。
- 共享 Cookie 版本变化会标记增强解析需要重启；停用代次时移除该订阅。
- 管理页 `/bili/*` 错误统一为有限安全文本，不序列化原始接口错误。
- 新增管理页“发送到群”复选框、单个群选择框、刷新群列表和单独保存目标；默认仍是主人 C2C，管理命令和领取仍在主人私聊。
- 新增 `bili-dm-groups.js`，只通过宿主 `ledger.stats()?.byChat` 的群类型行、运行时普通群消息观察缓存（最多 200）和 `ctx.getGroup` 校验群存在且启用；不读取宿主存储路径或群正文。
- 新增认证路由 `GET /bili/dm/groups` 和 `PUT /bili/dm/target`；后者只接受 `sendToGroup`/`groupId`，验证现有主人绑定后调用后续投递模块的 `configureTarget`，缺失时安全失败。
- 接收目标变更冻结旧目标未尝试批次，不自动补发 `sending`、`pending` 或 `unknown` 结果。真实群发送仍**待联调**。

### 文档与测试

- 新增 Node 集成测试，覆盖主人 C2C 门禁、全部命令、媒体开关关闭、Python 不可用、热重载写入交接、旧代次停用、请求体目标伪造、路由白名单和响应/页面泄漏。
