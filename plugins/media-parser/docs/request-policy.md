# 私信请求调度与恢复

适用版本：0.3.0。下列数值是插件采用的保守策略，不代表平台承诺的安全阈值。

## 请求范围

B 站私信同步、分页续拉、立即检查、账号校验、手动 Cookie 验证、二维码生成及查询都从同一个 Node 请求边界进入协调器。旧 `/bili/*` 和新 `/dm/providers/bilibili/*` 路由复用同一服务。

GET 状态只读取本地缓存和调度快照，不隐式检查账号或访问平台。前端的状态定时刷新与后台的上游轮询分别管理；折叠或离开页面不会关闭已启用的监听。

小黑盒尚未通过真实协议验证，本版不向其候选登录或私信路径发请求。预留平台视图不表示已经具备第二条真实私信链路。

## 参数

| 项目 | 策略 |
| --- | --- |
| 默认轮询 | 300 秒 |
| 可设轮询 | 180–3600 秒 |
| 周期抖动 | 在有效间隔上增加 0–20% |
| 请求间隔 | 至少 5 秒，另加 0–2 秒 |
| 平台总预算 | 10 次／60 秒，含扫码和账号检查 |
| 平台数据预算 | 6 次／60 秒 |
| 同步单轮预算 | 最多 6 次；未完成时保留精确续拉位置 |
| 并发 | 同平台串行调度，同账号不会并行访问 |
| 扫码查询 | 不短于 5 秒，并受总预算与二维码期限约束 |
| 手动登录检查缓存 | 10 分钟，按实际凭据区分，凭据变化立即失效 |

同宿主进程内的机器人和模块快照共享平台调度预算。状态文件位于各插件数据目录；重载和重启继续使用持久化元数据。独立宿主进程、其他软件及同一公网 IP 的总流量不受本插件统一控制。

## 拒绝分类

HTTP 429 与已确认的限流信号触发冷却；首次至少 15 分钟，连续限流逐级延长到 30、60 分钟。有效 `Retry-After` 支持秒数和 HTTP 日期，服务器要求的更长时间不会被本地上限缩短。

HTTP 403/412 本身不证明登录失效、验证挑战或限流。B 站按可信业务响应识别 `-101` 登录失效及 `-412` 拒绝；不把这些数字含义套到其他平台。普通超时、网络失败及临时 5xx 使用退避，结构异常保留同步进度并低频探测。

明确登录失效时等待换凭据；确认验证挑战时暂停自动动作。用户取消和旧代次失效不作为平台故障反复通知。

## 恢复与人工处理

冷却到期只放行一个完整恢复工作流。该流程可以跨页、跨轮续拉；某一页 HTTP 200 或一次账号检查成功不会清空完整同步的拒绝历史。连续 3 次恢复探测被拒绝后，需要人工恢复。

B 站在原状态文件的 `syncCycles` 中保存有界的同步周期身份，分页和重载继续使用该身份，完整成功后再生成下一周期。成功回调使用发起本轮时固定的账号作用域，旧账号迟到的结果不能清除新账号冷却。后台定时器采用当前有效间隔，并叠加向上的随机延迟。

主人在普通 C2C 中可发送：

```text
/解析 私信 B站 状态
/解析 私信 B站 恢复
/解析 私信 B站 检查
```

“恢复”只释放下一次受控探测，仍保留尚未结束的服务端等待；它不删除队列或跳过验证。有效间隔可能因退避而增加，连续 5 次完整同步成功后逐级缩短，始终不短于用户设定值。

退出登录、启停提醒、保存间隔、切换平台、刷新页面和热重载都不能清空有效的平台冷却。扫码剩余寿命不足以覆盖排队或冷却时结束该会话，等待用户重新发起。

## 状态文件与故障

`private-message-request-state.json` 只保存账号命名空间、预算、时间和安全原因码，不保存 Cookie、二维码密钥或私信正文。写入使用串行原子替换。

文件损坏、版本不支持、读取或持久化失败时，请求进入安全暂停；保留原文件和原 B 站队列供核对。不要通过删除状态文件或回退版本来绕过等待。升级、备份及回退步骤见 [迁移与回退](../MIGRATION-ROLLBACK.md)。
