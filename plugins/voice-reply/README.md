# 语音回复 · Roost 扩展

版本 **1.1.6**。把原 `voice-reply` 框架插件的角色语音合成迁入 **Roost 面板「扩展」**，管理页面位于 **表达 → 语音回复**。

本包属于 Roost 扩展市场，清单使用该市场约定的 `kind: "dsh-extension"`；不是安装到 DSH 主程序插件管理器的 Cordis bundle。发布目录是 `plugins/voice-reply/`。

## 功能与工作方式

- 独立调用 GPT-SoVITS v2，每个任务先确认 SoVITS / GPT 权重，再合成角色语音，不依赖内置 TTS 开关。
- 音色方案把 API、SoVITS/GPT 权重、参考音频、参考文本、参考/正文语言、语速、切句、句间停顿、top_k/top_p/temperature 与复用开关保存为一套，最多 50 套。已有方案改名保存更新原 ID，另存需要显式新建。旧版 8 字段方案自动补齐新参数。
- 支持本机一键启动/关闭 GPT-SoVITS，使用独立进程和持久日志，不依赖当前聊天任务存活；启动后按钮切换为「关闭服务」，加载中也可取消。关闭完成恢复为启动，退出中显示进度；外部入口启动的服务显示其状态并提示在原位置关闭。安装目录是全局设置，默认留空。
- 自带启动适配器增加语义缓存：相同正文复用上次完整的 GPT 语义结果来调速或更换音色，不用固定随机种子冒充复用。原生 v2 API 仍可普通合成；复用需要适配器提供的接口。
- 冷却、台词、启用开关和翻译密钥等仍是全局设置。
- 支持中、日、英正文，默认按内容识别语言；参考音频语言与正文语言分别配置。纯汉字日文请将正文语言显式选为 `ja`。
- 有正文时读正文，不会因翻译未配置而丢弃正文、改读无关台词。可选 OpenAI 兼容翻译接口先译为日语；翻译失败保留原文，并返回说明。
- 无正文时抽取短句台词；自定义台词优先，按会话避开最近 8 句。保留原插件的 24 句日语台词。
- 语速、最大正文长度、冷却和总超时可配置。默认最多 60 个字符、语速 1、冷却 3 秒、总超时 60 秒。
- 面板可检查服务接口、编辑全部设置与台词、生成本地试听。试听为后台任务，页面轮询结果，完成后提供 WAV 播放器；试听不发 QQ。
- 聊天语音先转换为 QQ 可用的 SILK，校验格式、时长和解码后音量，再把 `<<voice: 完整路径>>` 返回给宿主发送。静音、截断、超大响应及合成失败都不返回语音标记。

**触发方式是移植中的明确差异：** 原框架插件在消息监听器中按关键词匹配并 `msg.claim()` 认领消息；当前 Roost 扩展接口没有这类消息拦截钩子。本扩展通过聊天模型调用 `voice_reply` 工具触发，扩展自带 `usage` 提供调用约定，不修改任何人格。模型选择是否调用、最终是否正确输出标记，都属于宿主对话链路；关键词配置不是一个后台关键词监听器。

用户问问题并要求语音答复时，模型应先组织简短答案，再把答案放进 `text`，而不是把“今天的天气怎么样”原句当答案念出来。单纯要求复述时传待朗读的原文；只要求随口说一句时可不传正文。

## 依赖

| 依赖 | 要求 |
|---|---|
| Roost 扩展宿主 | 已验证 `dsh-roost 1.3.15` 的清单、配置、面板动作、MCP 和出站标记契约 |
| QQ 框架 | 已核对 `qq-bot-roost 1.1.5` 的语音上传路径；由宿主继续处理会话和 QQ 发送 |
| Node.js | 22 或更高版本，能执行清单的 `node server.mjs` |
| GPT-SoVITS | 已启动 `api_v2.py`，提供 `/tts`、`/set_sovits_weights`、`/set_gpt_weights`；WebUI 地址和旧 `api.py` 不适用 |
| 音色素材 | 自行准备 SoVITS 权重、GPT 权重、参考音频及准确原文，本包不附带模型和音色素材 |
| SILK 编码 | 包内附带 `silk-wasm 3.7.1` 的 ESM/WASM 分发文件、MIT 许可证及 SHA-256 来源记录，安装无需运行 npm 安装脚本 |
| 可选翻译 | 兼容 OpenAI `/chat/completions` 的接口及模型；启用后正文会送往该配置地址，可能产生接口费用 |

不需要 `agent:write`、`prompt:write`、`config:write`、`message:write` 等宿主 `/v1` 权限，清单显式声明 `scopes: []`。当前宿主将自带同源页面与 `inprocess` 执行形态纳入分级，推导级别为 L3；旧宿主只看 scope 时曾显示 L0。本包仍显式声明空 scope，自带页面及进程内启动器具有本地文件、网络与子进程访问能力，分级不代表进程隔离。

## 安装与配置

1. 运行时安装通过 **Roost → 扩展 → 市场** 的正式流程完成，发布前可使用自己的测试市场源或隔离审核环境。解压审查包得到的 `plugins/voice-reply/` 是完整提交目录，压缩包本身不是 DSH 主程序插件安装包。仅把目录复制进 `extensions/` 会被当前宿主视为只读的手写扩展，不会自动写入 MCP 受管配置，面板也不允许保存设置；请勿将复制目录当作完成安装。离线审查可直接在交付目录运行下文测试，无需改现有安装。
2. 到 **表达 → 语音回复** 新建方案，填写方案名、API 地址、参考音频路径、参考文本、参考语言和两套权重路径，点击「保存方案」再「应用方案」。API 默认值是通用的 `http://127.0.0.1:9880`；所有音色路径默认留空，没有作者机器路径或凭证。下方「保存全局设置」单独保存安装目录、冷却、台词与翻译等，不会隐式应用音色草稿。
3. 点「检查 GPT-SoVITS 服务」确认 v2 接口齐全，再生成一条试听，亲自播放检查音色与声音。接口检查通过只表示端点存在；试听通过也不等于 QQ 已送达。
4. 聊天里试「说话」「发个语音」「用语音回复：今天辛苦了」等请求。群聊仍需先满足宿主的接话/提及规则和该会话的扩展工具权限。
5. 正式切换时在 Roost 框架插件页停用旧 `voice-reply`，保留其设置以便回滚。同一个用户请求同时走旧插件和扩展，可能产生重复回复；两个入口共用一个 GPT-SoVITS 进程也可能互相切换角色。

本机启动：填写并保存「GPT-SoVITS 安装目录」，点击「一键启动服务」。目录应包含 `api_v2.py` 及 `runtime` 或 `.venv/venv` Python 环境。按钮使用当前 API 地址的端口，不自动漂移端口；只支持本机 HTTP 根地址，远程服务由对应机器启动。已有服务就绪时不重复创建进程。启动日志与 PID 记录位于 `<Roost 数据根>/extension-data/voice-reply/services/`，页面显示启动中、就绪或错误并可查看日志。

启动器以固定参数、`shell:false` 启动包内 `service-runner.py`，将标准输出和错误写入文件，子进程独立运行。适配器在内存加载已有 GPT-SoVITS API，增加复用接口，不覆盖 GPT-SoVITS 源文件、模型或依赖。卸载扩展不会自动终止已独立运行的语音服务。

也可手动启动原生 API（不含语义复用接口，将目录替换成自己的安装位置）：

```bat
cd /d GPT_SOVITS_DIR
runtime\python.exe api_v2.py -a 127.0.0.1 -p 9880
```

路径都以 **GPT-SoVITS 服务所在机器** 为准。权重通常填相对该服务工作目录的路径，如 `SoVITS_weights_v2Pro/角色.pth` 与 `GPT_weights_v2Pro/角色.ckpt`；也可使用该服务接受的绝对路径。远程服务上的参考音频不要求存在于扩展所在机器。

设置由 Roost 原生配置机制保存：普通设置在 `<Roost 数据根>/extensions/voice-reply/config.json`，翻译密钥独立存于 `<Roost 数据根>/secrets/voice-reply.config.json`，页面仅显示“已设置”。密钥框留空保留现有值，明确勾选清除才删除。聊天工具没有设置修改接口。

扩展每次任务重新读取设置；删除配置文件表示恢复默认，不会退回 MCP 进程启动时的旧设置。1.1.3 的面板使用新入口并为服务依赖带上版本，避免升级后混用旧 ESM 模块；更新 MCP 代码仍需让宿主重新建立工具连接。

1.1.5 修复了 1.1.3 → 1.1.4 同进程升级时的方案误报：方案模块曾引用裸路径的旧配置校验器，导致合法 14 字段数据被旧 8 字段表误判为损坏。方案模块、服务启动依赖现在都按安装版本加载，面板入口也升级以刷新工厂缓存。新增热升级回归会在同一 Node 进程先缓存旧字段表，再读取新版方案，确认无需清空文件或重启宿主。

### 保存和切换音色方案

1. 页面默认选中正在使用的方案。修改名字后点击「保存方案」，保持原 ID，不会新建副本；仅改名时不需要覆盖确认。音色参数也改动时会提示覆盖原方案。
2. 点击「新建方案」会清空方案名，将全部 14 项音色设置恢复原生默认值：权重、参考音频与原文变为空白，API、语言及采样参数恢复通用默认；全局设置和密钥保留。填写名称和必需音色参数后保存，相同内容未选原 ID 时会提示选择原方案改名。
3. 选择方案并点击「应用方案」，覆盖该方案的 14 个音色字段，全局设置和密钥保留；页面中尚未保存的全局编辑也保留。下一次合成读取新方案，已开始的任务使用原配置快照。保存方案本身不隐式应用；全局保存也不隐式提交方案参数。
4. 未修改时「保存方案」置灰，修改方案名或任一音色参数后显示未保存提示；改回原值会恢复灰色。全局设置和密钥改动独立处理。
5. 切换方案、新建、刷新列表或应用前，若有未保存的方案修改，显示「保存并继续 / 放弃修改 / 取消」；没有修改直接执行。保存失败保留草稿与原选择，取消也保留，明确放弃才载入新值。
6. 删除只删保存项，正在使用的音色配置保留。

「怎么切句」支持不切、凑四句、凑 50 字、中文句号、英文句号和标点切分；句间停顿默认 0.3 秒。采样参数默认 top_k=15、top_p=1、temperature=1，滑块与数字框同步。勾选「复用上次语义结果」后，相同正文/语种/GPT 模型和切句批次可复用上一次完整语义，语速与 SoVITS 音色可改变；首次无匹配缓存会正常采样并建立缓存，失败任务不覆盖上次完整缓存。普通 API 缺少该接口时页面会提示服务能力，保留用户开关值，不把种子复现当作缓存命中。

方案保存于 `<Roost 数据根>/extension-data/voice-reply/profiles.json`，与代码、原生配置和密钥分开，更新扩展不会清除。独立短锁协调多进程保存，不等待语音合成长队列；文件损坏时保留原文件并明确报错。与宿主原生配置保存的外部并发通过快照检查防止常见覆盖，建议不要同时在两个页面编辑同一份配置。

## 工具与面板动作

### `voice_reply`

```json
{ "text": "今天辛苦了，早点休息。", "chatId": "当前会话标识" }
```

- `text`：准备好的答复或待复述原文，留空抽台词。
- `message`：可选原始点播请求，只在 `text` 留空时解析关键词后的正文；不匹配就返回文字模式。
- `chatId`：用于冷却和台词去重，不是身份凭据。省略时共用默认冷却；扩展不通过它选 QQ 收件人。

成功结果包含 `mode: "voice"`、`reply`、`generated: true` 和 **`delivered: false`**。`reply` 默认只有一个指向 `.silk` 的 `<<voice: ...>>` 标记；勾选「语音附带文字」才额外带朗读正文。模型应原样输出 `reply`，不要再调用 `qq_send` 或内置 `<<say:>>` 重发。

本工具负责合成与交给宿主，不拥有 QQ 送达回执；生成成功不会宣称已经发出。失败返回 `isError: true`、文字原因，且没有语音标记。

### `voice_status`

读取启用状态、缺少的设置、台词数量与脱敏的最近任务摘要。**不返回最近合成正文、密钥或本地数据目录**，避免一个 QQ 会话从状态工具读到另一个会话的正文。完整试听详情仅在主人面板展示。

面板动作包含 `status`、`probe`、`startPreview`、`job`、`audio`、`profiles` 与 `service`。`service` 接受 `status/start/stop`，关闭前核对受管 PID 的实际 Python、启动脚本、安装目录和 API 端口，兼容旧版启动记录；外部服务不会被终止。此进程管理只向主人面板开放。`profiles` 接受 `list/save/apply/remove` 操作，由主人面板管理自有音色配置，不向聊天工具开放设置修改。它们共享同一套业务逻辑；没有独立的模型调用，没有给任意 QQ 会话主动发送的动作。

## 发送链路、并发与数据

```text
用户语音请求 → 宿主模型调用 voice_reply
            → 配置/冷却检查 → 切 SoVITS 与 GPT 权重 → /tts 请求 WAV
            → 验证音轨 → 规范声道/位深 → SILK 编码并解码验音
            → 返回 <<voice: 扩展数据目录中的.silk>>
            → 宿主出站执行器 → QQ 框架上传发送
```

- 所有合成入口共用文件锁，覆盖权重切换、合成和编码，MCP 与面板不会在本扩展内部并行换错音色。它不锁住其他插件或直接请求 API 的客户端。
- 每个任务重新确认权重，避免旧插件 30 分钟权重缓存跨服务重启失效。排队、翻译、模型加载和合成共用总超时，HTTP 读取到响应体结束也受取消信号约束。
- WAV 上限 10 MiB、有效时长 0.1–55 秒。支持常见 PCM / 浮点 WAV，转换成单声道 16bit，保留采样率和增益后交编码器处理，不依赖 ffmpeg。
- 默认数据位置是 `<Roost 数据根>/extension-data/voice-reply/`，由实际安装目录推导，不依赖用户名。音频在 `audio/`，任务在 `jobs/`，冷却/最近台词在 `cooldowns/`；这些不写入发布目录。
- 下次合成前清理超过 24 小时的自有记录；近期生成记录最多约 120 项（音频按 WAV/SILK 两份约 240 个文件，3 分钟内的活跃文件暂缓清理）。这不是定时后台清理器。
- 已退出进程的锁可回收；空/损坏锁保守等待 180 秒后回收，不抢占仍在运行的进程锁。

**配额说明：** 已核对的宿主版本对 `<<voice:>>` 分支不扣内置 `voice` 配额；扣额代码在 `<<say:>>` 分支。本包提供自己的会话冷却，但不把它当作身份权限或平台配额。QQ 的发送窗口、授权和发送失败仍由宿主/框架处理。

## 与框架版的对应关系

| 原框架功能 | 扩展实现 |
|---|---|
| GPT-SoVITS、角色权重、参考音频 | 保留，默认音色参数留空 |
| `silk-wasm` 编码 | 保留并随包分发，增加静音/解码检查 |
| 中文、日语正文与可选翻译 | 保留，翻译失败念原文 |
| 台词库、自定义台词、最近去重 | 保留，自定义台词在面板维护 |
| `/语音 开/关/语速/台词` 管理指令 | 转到主人面板的对应设置；不注册 QQ 管理斜杠命令 |
| 关键词监听与 `priority: 80` / `claim()` | 改为模型调用工具；不承诺每次文本关键词都被确定性拦截 |
| `replyNote` | 保留；只有启用时附正文 |
| 失败提示 | 工具返回结构化文字原因，试听面板显示错误；不额外偷偷发 QQ |

## 检查与审查要点

普通自动化测试不依赖 QQ、个人配置或正在运行的 GPT-SoVITS：

```bash
node --test test/*.test.mjs
```

额外运行已安装宿主的真实清单与出站执行器契约：

```bash
DSH_ROOST_DIR=/path/to/dsh-roost node --test test/*.test.mjs
```

本轮在上述已安装宿主上运行：**79 项 Node 检查通过、0 失败、0 跳过**，另有 **15 项 Python 语义缓存/适配器检查通过**，包含两个真实 MCP 子进程并发请求的锁验证，以及在临时数据根通过宿主正式 registry 安装、配置读写、密钥遮蔽和升级保留设置的检查。未指定 `DSH_ROOST_DIR` 时，依赖宿主的三项测试会明确跳过；不是假装通过。测试使用临时目录与本机临时 HTTP 服务，WAV→SILK 测试使用包内真实 WASM 编解码器。出站执行器测试使用真实宿主模块与假 QQ 通道，不向真人发消息。

适配器的独立 Python 测试使用 GPT-SoVITS 自带 Python 环境运行 `PYTHON -B test/service-runner-test.py`，需要该环境已有的 NumPy、FastAPI/Starlette；不加载真实 GPU 模型。覆盖语义缓存命中/失效、模型重载、设备回放、失败不污染、缓存界限、请求串行与启动参数。没有 FastAPI/httpx 的普通 Python 里，真实 FastAPI 路由那条会**显式跳过**而不是报错失败（本轮该环境为 14 通过 + 1 跳过；GPT-SoVITS 自带环境内 15 项全部通过）。

重点检查：

- 清单与包版本一致，`id` 和目录名相同，`usage` 未超过宿主 200 字上限，面板导航在 `express`。
- 不夹带旧插件的 `.roost-cache`、`node_modules`、参考音频、模型、用户设置、token 或密钥；文本 LF 换行。
